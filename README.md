# 重命名预览 · 逐处确认（Rename Preview）

一个**纯浏览器本地**的 TypeScript 重构工具：对一次重命名不做盲目全文替换，
而是由 TypeScript Compiler API 按**符号绑定**算出全部位置，让开发者**逐处确认**。

- 局部变量 / 参数、对象属性、字符串内容、同名但不同作用域的标识符，按符号绑定区别处理；
- 遇到动态访问等无法静态分析的位置，列入**未覆盖位置**，绝不自动改；
- 触发文件有语法错误时**保留草稿**，不生成任何替换；
- 一次跨文件重构提交前复核**共同版本**；撤销按**整次操作**恢复；
- 只改动符号自身的文本区间，尽量保留原注释与无关空白/格式；
- React + Monaco 编辑，TS Compiler API 运行在 **Web Worker**，文件与操作历史存 **IndexedDB**；
- **不运行任何被导入的用户代码、不访问后端、不读磁盘 node_modules**（`noLib`，外部依赖不解析）。

## 启动

```bash
npm install
npm run dev        # 浏览器打开 Vite 给出的地址
npm run build      # 类型检查 + 生产构建
npm run selftest   # 在 Node 中直接跑同一套分析引擎的 20 项断言
```

界面右侧「工程自测」标签页还能在浏览器 Worker 里运行**同一套**自测。

## 三类标记（决定哪些改动已被证明）

| 标记 | 含义 | 默认 |
| ---- | ---- | ---- |
| ✓ 已证明（绿） | 编译器可证明该位置属于目标符号（含 `u['name']` 这类接收者类型可解析的字符串键，以及简写属性展开） | 勾选 |
| ○ 需人工判断（黄） | 字符串键/普通字符串、`obj[expr]` 动态访问、接收者类型不可解析（如 `any`、未解析依赖） | 不勾选 |
| ✕ 同名不同绑定（灰，删除线） | 名字相同但属于别的作用域/绑定（遮蔽变量、参数、另一个属性等） | 永远不改 |

## 关键安全机制

1. **符号绑定而非文本**：排除项给出人类可读的作用域说明（如「for 循环的 const 声明」「函数 inner 的参数」）。
2. **类型与值同名**：`type Box` 与 `const Box` 是两个符号；在类型位置改名不动值表达式，反之亦然。
3. **分析期间再次编辑**：每次分析记录每个文件的 `rev + 内容哈希`；Worker 返回时与提交前都会复核共同版本，
   一旦漂移即锁定提交并把预览标记为过期，要求重新分析。
4. **整次操作原子提交/撤销**：跨文件改动与历史快照在同一个 IndexedDB 事务内写入；
   撤销直接恢复该操作前的整批文件快照（不会只回滚半个文件）。
5. **重叠区间保护**：应用编辑前按下标排序并校验区间，任何重叠即拒绝提交。

## 内置验证工程

顶栏一键载入，光标会自动放到建议的标识符，直接按 **F2**：

- **变量遮蔽**：外层 `count` 与 for 循环绑定、函数参数、对象属性是四个符号；
- **类型与值同名**：`type Box` 与 `const Box` 分别在类型侧/值侧重命名；
- **属性·字符串·动态访问**：可证明属性、可解析字符串键、普通字符串、`u[dynamicKey]` 与 `any.name` 分组呈现；
- **跨文件改名**：`src/types.ts` ↔ `src/app.ts` 联动，提交前复核共同版本；
- **语法错误保留草稿**：触发文件含语法错误时只显示错误并可点击跳转，不产生替换。

验证「分析期间再次编辑」：发起重命名后，在编辑器里继续输入，右侧预览立即变为
过期横幅并锁定提交按钮。

## 目录结构

```
src/
  engine/      TS Compiler API 分析引擎（纯逻辑，Node 与 Worker 复用）
  worker/      Web Worker 封装与主线程客户端
  shared/      通信协议、纯文本 edit、哈希
  storage/     IndexedDB：文件、整次操作历史
  editor/      Monaco 离线初始化
  ui/          React 界面、逐处确认面板、提交/漂移校验
  scenarios/   内置验证工程
  selftest/    20 项引擎断言（遮蔽/同名/动态访问/语法错误/格式/漂移）
```
